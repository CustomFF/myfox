# MyFox — как устроено

MyFox ставит Firefox (stable или beta) из официального тарбола Mozilla в каталог пользователя и
применяет к нему твики из [CustomFF/myfox-tweaks](https://github.com/CustomFF/myfox-tweaks). Root не нужен.
Код — пакет `myfox/` на Python 3.8+, только stdlib; сторонний чистый Python — исходниками в
`myfox/_vendor/` (picotui, jeepney), бинарный dearpygui — из собственного релиза.

Твики (что именно меняется в браузере и как) описаны в самом репозитории tweaks; здесь — только
как установщик их доставляет. Букмарклеты — отдельный проект ddblm, установщик копирует его
готовые CSS и иконки.

## Источники и треки релизов

| Что | Откуда | Тег | Обновляет |
|---|---|---|---|
| Ядро (пакет `myfox/`) | релизы этого репозитория: `myfox-core.tar.gz`, `changelog.json` | `core-<semver>` | `myfox refresh` |
| Твики (`autoconfig/`, `chrome/`) | релизы CustomFF/myfox-tweaks: `myfox-tweaks.tar.gz`, `changelog.json` | `<beta major>.<patch>` (`158.0`) | `myfox refresh` |
| Темы (два `.xpi` в профиль) | релизы CustomFF/myfox-tweaks | `themes-<время сборки>` | `myfox refresh`; скачиваются, только если релиз новее записанного или файла нет |
| Оформление букмарклетов (`blm_panel.css`, `panel-icons/` в `chrome/` профиля) | master ddblm, без релизов | `ddblm-<время коммита>`: последний коммит, менявший `docs/blm_panel.css` или `icons/` | `myfox refresh`; файлы берутся из этого коммита, только если он новее записанного или CSS нет; GitHub API недоступен при установке — из master без записи версии |
| dearpygui (для GUI) | релиз этого репозитория, колёса cp38–cp314 × x86_64/aarch64 | `dearpygui-2.3.1` | при установке; заново — после смены версии Python |
| Firefox | `download.mozilla.org` | — | обновляется сам; заново — `myfox reinstall` |

Версии сравниваются как числа (`changelog.py`); `core-` в интерфейсе не показывается, теги тем и
ddblm показываются датой (`2026-10-01 15:46`).
`changelog.json` — накопительный, новые версии первыми; «Что нового» — строки новее установленной.

## Точки входа

```
get.sh          curl -fsSL …/get.sh | sh [-s -- аргументы]
                нужен python3; скачивает bootstrap.py и запускает его, отдав ему терминал (/dev/tty)
bootstrap.py    MyFox уже стоит → аргументы уходят в установленный `myfox`; без аргументов —
                «уже установлен» и вопрос «проверить обновления?» (без терминала — команда)
                не стоит → ядро последнего core-* во временный каталог (+ dearpygui для --gui)
                и `python3 -m myfox.wizard` оттуда
myfox           ~/.local/bin/myfox → ~/.local/share/myfox/bin/myfox (sh: python3 -m myfox)
```

Подкоманды `myfox` (`__main__.py`): `browser [аргументы Firefox]` (exec обёртки
`<install>/firefox-myfox`), `refresh [--force]`, `reinstall`, `uninstall [--remove-profile] [--no-restore-sync]`,
`command [on|off]`, `help`,
`--version`. Общие флаги: `-y` (без вопросов), `--gui` (окно). Подкоманды `install` нет:
первая установка — только из `bootstrap.py`.

## Как показывается интерфейс

Логика одна, видов три; `--gui` меняет только вид.

- **Форма первой установки** — `install_form.InstallForm` (ответы, выбор, проверка каталога, языки
  Firefox с поиском) и виды `ui/form_gui.py` (dearpygui), `ui/form_tui.py` (picotui),
  `ui/form_plain.py`.
- **Диалог команды** (refresh, reinstall, uninstall) — `task.Task`: строки, необязательный список,
  галочки, одна кнопка действия, прогресс, «Закрыть». Виды `ui/task_{gui,tui,plain}.py`, выбор —
  `task.show()`. Разрушительное действие начинает с фокуса на «Отмена»; если действие сейчас
  невозможно (запущен Firefox из этой установки), причина показана, кнопка недоступна. Пока диалог
  ждёт, причина перепроверяется раз в секунду (`Task.recheck`): закрыли Firefox — кнопка доступна,
  запустили — снова нет; перед самим запуском — ещё раз. Фокус при этом не прыгает на действие.

Выбор вида: `-y` → текстовый, без вопросов; `--gui` → окно (не открылось — терминал, а без терминала —
уведомление); терминал → TUI; иначе текстовый. **Текстовый вид никогда не спрашивает** — вопрос в
трубе никто не увидит: без `-y` он печатает сводку и команду с `-y` и выходит с кодом 1.

GUI: перед первым окном `gui_deps.prepare()` открывает пробное окно в дочернем процессе (таймаут),
при неудаче повторяет с `LIBGL_ALWAYS_SOFTWARE=1`. Колесо dearpygui проверяется по метке
`.myfox-wheel`: сменилась версия Python — колесо перекачивается до импорта.

## Первая установка (`installer.install`)

Поля формы: каталог (по умолчанию `~/.local/share/myfox/firefox`), канал, профиль (новый, свои
`myfox-*`, «Импорт: <профиль>» другого Firefox — из `sources.listing()`, — или «Импорт из папки…»;
флаг мастера `--import <ID|имя|папка>`), синхронизация (только при импорте профиля со входом в
аккаунт: оставить / перенести / копировать, `--sync none|move|copy`), твики да/нет, оформление и DNS через HTTPS да/нет (только при твиках; DoH по умолчанию да, флаг
мастера `--no-doh`), команда оболочки firefox да/нет (по умолчанию нет; флаг
мастера `--firefox-command`), язык Firefox (по умолчанию из
`$LANG`; список — с Mozilla до показа формы, без сети форма показывает ошибку и не ставит).
Импорт: открытый профиль не пускается («сначала закройте Firefox»); профиль от более новой версии,
чем ставится канал (`firefox.latest_versions()`), — предупреждение, повторное «Установить» значит
«на свой страх и риск»; с `-y` — отказ без `--allow-downgrade`.

1. Firefox: тарбол в каталог (наш уже стоящий — переиспользуется), метка `.myfox-installed`.
2. Профиль: выбранный или новый `myfox-N` (метка `.myfox-created`). При импорте в новый копируется
   выбранный (`importer.copy_profile`, прогресс по байтам, отмена — откат); с согласием на понижение
   версии копия один раз открывается headless с `--allow-downgrade`. Перенос синхронизации —
   последним шагом перед state (единственное изменение чужого профиля; откат возвращает аккаунт).
   В state: `import_source`, `import_sync`, `import_backups`.
3. При твиках: релиз твиков в `~/.local/share/myfox/tweaks`; пиннинг профиля; `autoconfig/` в
   установку, `chrome/` и метка `.myfox` в профиль; `myfox.theme` в `user.js`, при DoH «нет» — и
   `myfox.doh = false` (твики включают DoH при первом запуске профиля, если этого нет); обе темы в
   `<profile>/extensions/`; букмарклеты из ddblm (недоступен — предупреждение, не ошибка).
4. Сессия KDE Plasma и твики: аддон интеграции с AMO; нет системного пакета
   `plasma-browser-integration` — заметка с командой установки в конце.
5. Себя — в `~/.local/share/myfox/myfox`, лаунчер `bin/myfox`, симлинк `~/.local/bin/myfox`;
   dearpygui рядом; ярлык.
6. Если выбрана команда оболочки firefox — она (см. ниже); её предупреждения — в `answers.notes`.
7. State.

После успешной установки форма (TUI и GUI) закрывается сама, а в терминал печатается сводка
(`install_form.summary`: версия Firefox, каталог, профиль, канал, твики, оформление, язык, как
запустить). При ошибке форма остаётся с ошибкой и кнопкой «Закрыть». То, что нужно сказать после
закрытия формы (пиннинг не удался, нет пакета Plasma, GUI не поставился), копится в
`answers.notes` и печатается после сводки.

Отмена во время установки: «Отмена», Esc, ^C (TUI), крестик окна (GUI), ^C и SIGTERM (`-y`),
закрытый терминал (SIGHUP). Работа идёт в отдельном потоке (`-y` — в основном) и видит запрос при
следующем отчёте о прогрессе (`install_form.Cancel`): она бросает `Cancelled`. Ошибка или отмена —
`installer` откатывает созданное в этом запуске: каталог Firefox (уже стоявший наш не трогается,
пустой — только очищается), новый профиль с его секцией и `[Install<HASH>]`, `profiles.ini`/
`installs.ini`, если их не было, новое в `~/.local/share/myfox`, ссылку `myfox`, ярлык, команду
оболочки. Последний отчёт («Готово») уже не отменяет. Форма после отмены закрывается, в терминал —
«Установка отменена…».

Сеть: таймаут — 20 с без ответа (`net.TIMEOUT`, в `bootstrap.py` свой). Тарбол Firefox качает
`net.download`: чтение в отдельном потоке, поэтому пока сеть молчит, раз в секунду идёт отчёт
«… нет ответа сети: N из 20 с» (и отмена срабатывает сразу); через 20 с — ошибка.

## Обновление (`refresh.py`)

Сначала проверка треков (темы — только при твиках и профиле, букмарклеты — ещё и если они ставились). Нового нет (и нет `--force`) → одна строка или уведомление, без
диалога. Есть → диалог: «старая → новая» по трекам и «Что нового». Не влезающий список кончается
строкой «…и ещё N»; если у установленных твиков есть `about:myfox` (`CHANGELOG_SINCE_TWEAKS`), это
ссылка (в TUI — кнопка), открывающая `about:myfox#changelog` в Firefox этой установки. `--force` берёт все треки, у
которых есть релиз. Порядок: твики (скачать, применить к установке и профилю, записать версию), темы (оба
`.xpi` в профиль, записать версию), оформление букмарклетов (в профиль, записать версию), потом ядро (заменить `share/myfox/myfox`; новый код работает со следующего запуска).

Ярлык и обёртка `firefox-myfox` рендерятся из `myfox/templates/` установленной копии MyFox
(подстановки `@WRAPPER@`, `@FIREFOX@`, `@LAUNCHER@`, `@ICON@`) и пишутся, только если отличаются.
`refresh` сверяет их при каждом запуске (обновление, сделанное старым MyFox, их не трогало) и сразу
после замены ядра. Это делает уже новое ядро, отдельным процессом (`myfox _sync`, скрытая
команда): в памяти работающего `refresh` старый код, который не знает новых файлов и полей (так
`myfox.json` не появился бы до следующего `refresh`). Не запустилось новое ядро — старый код
перерисует что может, по шаблонам нового ядра. Ядра до 1.1.20 нового процесса не запускают, поэтому
при переходе с них новое появляется только со следующим `refresh`.

Твики Firefox читает только при старте. Если обновляется что-то кроме ядра, а Firefox этой установки запущен
с твиками, умеющими перезапуск (`RESTART_SINCE_TWEAKS`), в диалоге галочка «Перезапустить Firefox»
(включена; с `-y` — перезапуск). После обновления MyFox отвязанно запускает
`firefox-myfox --myfox-restart`: remoting передаёт флаг запущенному Firefox, обработчик из твиков
перезапускает его как штатный «Перезапустить» (с вопросами о несохранённом, сессия
восстанавливается). Окно GUI после такого обновления закрывается само: смотреть в нём больше
нечего.

## Переустановка (`reinstall.py`)

Firefox качается в соседний временный каталог и подменяет текущий только после полной загрузки —
обрыв или отмена (диалог `cancellable`) оставляют рабочий Firefox. После подмены отмена уже не
действует (`install_form.settled`): переустановка доводится до конца. Затем метка, обёртка и ярлык; при профиле с твиками — пиннинг и
`apply.reapply_tweaks()` с сохранёнными выборами. Профиль не трогается.

## Команда оболочки firefox (`command.py`)

Симлинк `~/.local/bin/firefox` → `<install>/firefox-myfox`: не алиас оболочки, поэтому работает и в
скриптах, и в других программах; на обёртку, поэтому ссылка уходит в уже запущенный наш Firefox.
Включается галочкой формы, флагом `--firefox-command` или `myfox command on`, выключается
`myfox command off`; `myfox command` без аргумента показывает, включена ли и что ей мешает.

- Чужой `firefox` там (файл или ссылка не на обёртку MyFox) переименовывается в
  `firefox.myfox-backup` и возвращается при выключении и удалении; диалог тогда начинает с «Отмена».
  При выключении возврат — галочка (снята при `--keep-backup`): без неё бэкап остаётся лежать.
  Если чужой `firefox` есть, а место бэкапа уже занято, включение отказывает — ни один из них не
  теряется. Ссылка на обёртку другой, уже удалённой установки MyFox не сохраняется.
- Перед включением — проверка `PATH` процесса: `~/.local/bin` нет в нём, или раньше стоит каталог с
  другим исполняемым `firefox` — предупреждение. Алиасы и функции из rc-файлов оболочки отсюда не
  видны (исполнять чужие rc нельзя), как и кэш путей открытых оболочек (`hash -r`).
- State не нужен: включена ли команда, видно по самой ссылке.
- Для программ (страница `about:myfox` в твиках): `myfox command [on|off] --json` ничего не
  спрашивает и печатает состояние JSON; поля — в [Интеграция с about:myfox](https://github.com/CustomFF/myfox/wiki/Интеграция-с-about-myfox).

## Связь с браузером (`<install>/myfox.json`)

Твики (`about:myfox`) управляют MyFox, запуская его команды; где он и что умеет, узнают из
`<install>/myfox.json` (поля — в [Интеграция с about:myfox](https://github.com/CustomFF/myfox/wiki/Интеграция-с-about-myfox)). Файл
рендерится из `myfox/templates/myfox.json` вместе с обёрткой и ярлыком (установка, переустановка,
каждый `refresh`), поэтому после обновления ядра в нём сразу возможности нового.

## Удаление (`uninstall.py`)

Секция профиля и `[Install<HASH>]` убираются из `profiles.ini`/`installs.ini`; удаляются Firefox,
ярлык, команда оболочки firefox (только наша ссылка, прежний `firefox` возвращается), симлинк `myfox` (только если он ведёт в нашу копию) и `~/.local/share/myfox`; state
очищается. Профиль остаётся на диске (его потом найдёт новая установка), если не выбрано «удалить и
профиль» / `--remove-profile` — и тогда удаляется только созданный MyFox (`.myfox-created`).
Если профиль импортирован с «Перенести» и исходный может принять аккаунт обратно
(`importer.can_restore_sync`: бэкап есть, заново в аккаунт не входили), в диалоге галочка «Вернуть
аккаунт Firefox в <исходный>» (включена; `--no-restore-sync` — снять). Пока исходный открыт в другом
Firefox, действие заблокировано (проверка раз в секунду, снятая галочка блок снимает). Возврат —
первым делом, до удаления чего-либо: `restore_sync` в исходном, а оставляемая копия выходит из
аккаунта (`importer.sign_out`), чтобы не было двух клиентов с одной идентичностью.
Пункта «удалить» в меню ярлыка нет намеренно: его легко нажать случайно.

## Профили (`profiles.py`)

- Каталог профилей — общий с обычным Firefox: `~/.mozilla/firefox`, если он есть, иначе
  `$XDG_CONFIG_HOME/mozilla/firefox` (так решает сам Firefox 147+).
- Трогаются только свои секции: `[ProfileN]` нашего каталога и `[Install<HASH>]` нашей установки.
  Чужие `[ProfileN]`, `[Install…]`, `Default=1` и каталоги — никогда. Новый `[ProfileN]` — `max+1`.
- **Пиннинг**: хэш установки считает только сам Firefox, поэтому установка один раз запускается
  headless (`--screenshot about:blank`, без `DISPLAY`/`WAYLAND_DISPLAY`), Firefox пишет свою секцию,
  её `Default=` переключается на наш профиль (в `profiles.ini` и `installs.ini`), а профиль, который
  Firefox создал при этом прогоне, удаляется.
- **Все видимые профили** (`sources.py`, для импорта и команд профилей): наш каталог, snap
  (`~/snap/firefox/common`) и flatpak (`~/.var/app/org.mozilla.firefox`, у обоих тот же выбор между
  `.mozilla` и XDG). Профили — из `profiles.ini` и из групп профилей (`Profile Groups/<StoreID>.sqlite`,
  оттуда же показываемые имена), плюс наши `myfox-*` с `.myfox-created` без записи. ID — имя папки,
  для snap/flatpak с приставкой `snap:`/`flatpak:`, для папки вне каталога — путь; имя годится, только
  если оно у одного профиля. Чей профиль: `.myfox` → MyFox; без неё — по `LastPlatformDir` в
  `compatibility.ini` (наша установка → наш, созданный через `firefox -p`; нет файла → не
  запускался; иначе чужой, только импорт). Занят — `lock` ведёт на живой процесс `firefox`; у
  flatpak pid из `lock` снаружи ничего не значит, там — любой процесс в cgroup flatpak-Firefox.
  Понижение версии — `LastVersion` профиля новее устанавливаемой (`firefox.latest_versions`).
- **Копия чужого профиля** (`importer.py`): всё, кроме `lock`/`.parentlock`, кэшей (`startupCache`,
  `cache2`, `shader-cache`, `safebrowsing`…), дампов падений, `chrome/` (твики приносят свой) и наших
  меток; только обычные файлы и ссылки. Перед копированием — проверка места; прогресс по байтам,
  остановка — исключением из него. Синхронизация: `none` — без `signedInUser.json`, `weave/` и
  `services.sync.*` (кроме выбора движков `services.sync.engine.*`, `declinedEngines`); `copy` — как
  есть; `move` — как есть, а исходный выходит из аккаунта (`move_sync_out`): `signedInUser.json` и
  `prefs.js` копируются рядом в `*.myfox-backup`, затем аккаунт и sync-настройки убираются.
  `restore_sync` возвращает аккаунт и sync-строки из бэкапа в текущий `prefs.js` (остальное, что
  поменялось с тех пор, остаётся); если исходный снова вошёл в аккаунт — не предлагается.

## Профиль-локальность

Твики работают только в профиле с меткой `.myfox` внутри установки с `.myfox-installed`:
`myfox.cfg` проверяет метку первым делом. Глобального ничего не пишется (`policies.json` нет), темы
и аддоны — в `<profile>/extensions/`. Другой профиль той же установки — обычный Firefox; удалённый
профиль не оставляет следов MyFox.

## Релиз ядра

Поднять `__version__` в `myfox/__init__.py`, добавить в `CHANGELOG.md` раздел `## <версия> — <дата>`,
закоммитить, запушить master, затем тег `core-<версия>`. Workflow `core.yml` проверяет, что все три
совпадают, и публикует `myfox-core.tar.gz` и `changelog.json`; установленные копии получают его через
`myfox refresh`. Локально те же файлы собирает `scripts/build-core-dist.sh [каталог]`.

## Переменные окружения для разработки

| Переменная | Что делает |
|---|---|
| `MYFOX_BOOTSTRAP_URL` | откуда `get.sh` берёт `bootstrap.py` (`file://…` — из рабочей копии) |
| `MYFOX_CORE_DIR` | `bootstrap.py` берёт ядро из этого каталога, не качая |
| `MYFOX_CORE_URL` | архив ядра (путь или URL) вместо релиза — для bootstrap и `refresh` |
| `MYFOX_TWEAKS_LOCAL` | твики и темы из локальной копии CustomFF/myfox-tweaks |
| `MYFOX_DDBLM_LOCAL` | букмарклеты из локальной копии ddblm |
| `MYFOX_DEARPYGUI_DIR` | каталог с колёсами dearpygui вместо релиза |
| `MYFOX_NMH_DIRS` | где искать native host Plasma (пустой каталог — «пакета нет») |
| `MYFOX_BIN_DIR` | куда класть симлинк `myfox` вместо `~/.local/bin` |
| `MYFOX_SANDBOX_KEEP_DESKTOP` | `scratch/sandbox.sh` не сбрасывает переменные сессии (тест Plasma) |
